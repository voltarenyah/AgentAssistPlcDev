# Workbench App Assistant Gateway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose a narrow, read-only C# gateway that gives the future App Assistant project-level context without exposing the PLC AgentLoop's raw MCP catalog.

**Architecture:** ApiHost builds responses from `WorkbenchRuntimeStateCoordinator`, existing workbench services, `WorktreeTaskStore`, and version-control/engineering read surfaces. Python will call these internal loopback endpoints. The gateway does not change UI selection and does not start a second MCP runtime.

**Tech Stack:** ASP.NET Core, existing `WorkbenchApiState`, `WorkbenchCoordinator`, `ApiMcpGateway`, `WorktreeTaskStore`, JSON/SSE-compatible HTTP.

## Task 1: Define gateway contracts

- [ ] Add `AppAssistantWorkbenchContext` containing snapshot, worktree summaries, selected focus, and available actions.
- [ ] Add `WorktreeTodosResponse`, `WorktreeHistoryResponse`, and `WorktreeSvnResponse`.
- [ ] Use opaque IDs in responses and never expose absolute repository/source paths to Python.
- [ ] Add a `sourceRevision`/`observedAt` field to each read response so the assistant can explain freshness.

Target routes:

```text
GET  /internal/app-assistant/workbenches/{workbenchId}/context
GET  /internal/app-assistant/workbenches/{workbenchId}/worktrees/{worktreeId}/todos
GET  /internal/app-assistant/workbenches/{workbenchId}/worktrees/{worktreeId}/history
GET  /internal/app-assistant/workbenches/{workbenchId}/worktrees/{worktreeId}/svn
GET  /internal/app-assistant/workbenches/{workbenchId}/actions
```

## Task 2: Compose the workbench context

- [ ] Implement `AppAssistantGateway.GetContextAsync(workbenchId)`.
- [ ] Include all registered worktrees and compact current Git/SVN/validation summaries.
- [ ] Include the current UI focus if it belongs to the requested workbench.
- [ ] Include action capabilities generated by C# guards, not model inference.
- [ ] Do not include PLC knowledge DB contents or source XML content.

## Task 3: Add todo and history readers

- [ ] Implement todo reads through the existing worktree task storage.
- [ ] Implement Git history reads through the existing version-control service/API surface.
- [ ] Implement SVN revision reads from existing worktree metadata and engineering-state/revision data.
- [ ] Bound result sizes: default to 20 todos and 30 history entries, with validated maximums.
- [ ] Return explicit `WORKTREE_NOT_FOUND` and `HISTORY_UNAVAILABLE` errors instead of empty invented data.

## Task 4: Add internal authentication and scope validation

- [ ] Require a loopback-only caller or an ApiHost-issued internal token for `/internal/app-assistant/*`.
- [ ] Validate that every worktree belongs to the requested workbench.
- [ ] Never accept a repository path, source root, or SVN URL from the Python service.
- [ ] Add tests for cross-workbench and cross-worktree access rejection.

## Task 5: Generate capabilities

- [ ] Add capabilities for `read_worktree_todos`, `read_commit_history`, `read_svn_state`, and `create_worktree`.
- [ ] Keep `create_worktree` disabled in this plan; expose its prerequisites and approval requirement for later Plan 4.
- [ ] Return blockers such as missing workbench metadata, busy operation, or unavailable version-control state.
